# Boring-Engineering v1.1: does boring stay correct while cutting code?

*2026-08-28. `muse-spark-1.2-contributor-free`. Single-shot generation on a seeded mini-repo.*

This is the first publishable benchmark for `boring-engineering`. It is deliberately written to be falsifiable — not to make boring look good, but to show where it wins, where it barely moves, and where a naïve "write less" prompt would break.

It is inspired by [ponytail's agentic benchmark](https://github.com/DietrichGebert/ponytail/blob/main/benchmarks/results/2026-06-18-agentic.md) and its honest response to [#126](https://github.com/DietrichGebert/ponytail/issues/126). We adopt the same two-axis structure (size + safety) and the same controls, but all tasks, prompts, and scorers are our own.

## Why a new benchmark was needed

The first single-shot benchmark for ponytail reported 80–94% less code. The authors themselves later flagged that as inflated: the baseline was a chatty bare model, so the metric counted prose and options, not code, and a single completion is not how an agent edits a real codebase.

All three points apply to our early runs. Starting in v1.1 we fix them:

| | before (v1.0) | v1.1 (this file) |
|---|---|---|
| unit | one prompt → largest code block | same — but labeled **generation benchmark** (Tier S), with a separate **agentic Tier A** scaffolded for the honest claim |
| baseline | same oneshot agent, no skill — good | same, plus two extra controls: **caveman** (terse prose, normal code) and **yagni-oneliner** (bare 7-word prompt) |
| task | 6 isolated stubs | **6 LOC-tier tickets** (each seeds a real file to reuse) + **6 surgical safety tasks** (adversarial execution) |
| LOC | block size | **block size for Tier S; `git diff` for Tier A** (when Tier A runs) |
| isolation | arm order rotated, sequential | plus **per-cell fresh sandbox**, `n=5`, UTF-8-correct harness (we hit and fixed a `¥` double-encoding bug that made one task look 90% → 100%) |

We keep Tier S because it is cheap and actually runs the code. We do not claim it as the final word — Tier A (real headless agent on a real template repo) is scaffolded in `benchmarks/agentic/` and will become the headline number once `n=4` agentic runs finish.

## Setup

- **Engine:** `opencode` `oneshot` agent, `tool:* = false`, `--pure`, `tool-less`. The skill is injected as a file attachment (`The attached file contains a coding task, optionally preceded by a ruleset...` + `-f prompt.txt`), so no multiline argv mangling.
- **Model:** `opencode/muse-spark-1.2-contributor-free` (free-tier, deterministic-ish at default temperature). One model for v1.1; the harness supports `agentrouter/claude-opus-5` and others via `opencode.json`.
- **Tasks:** 12 tickets, two tiers. Tier S = 6 LOC tasks (each a one-line ticket that seeds a file), Tier A-safety = 6 surgical tasks (each seeds a starter file, safety requirement left *implicit*).
- **Arms (v1.1):** `baseline` (no skill) · `boring-engineering v1.1` · `ponytail` (third-party) · plus new controls `caveman` and `yagni-oneliner` (bare prompt: *"Follow YAGNI principles, and prefer one-liner solutions."*). Arms differ only in the prepended ruleset file.
- **Isolation:** every cell gets a fresh `sandbox/<arm>__<task>__<run>/` with its own `package.json`, seeded files, and solution file. No shared history, `n=5` per cell, sequential execution to avoid gateway throttling.
- **Metrics:** `correct` (gate: `node test.mjs` exit 0), `safe` (gate: adversarial input, only for safety tier), `src_loc` (non-empty lines of the largest fenced block for Tier S; `git diff` for Tier A), `tokens` / `cost` / `latency` from gateway events.

## Tier S: size and correctness on coding tasks (6 tickets)

Each ticket is a one-line feature where the agent chooses how much to build. Mean of 5 runs.

| task (trap) | what the ticket temptingly invites | baseline | caveman* | yagni-1liner* | **boring v1.1** | ponytail |
|---|:---|--:|--:|--:|--:|--:|
| slugify (control) | trivial string chain | 13 · 100% | — | — | **3 · 100%** | 3 · 100% |
| parseQuery (native-platform) | hand-rolled parser vs `URLSearchParams` | 37 · 40% | — | — | **21 · 100%** | 13 · 80% |
| priceWithTax (reuse) | re-implement `formatMoney` vs reuse | 6 · 100% | — | — | **4 · 100%** | 5 · 100% |
| formatJpy (abstraction) | abstract `formatUsd`/`formatEur` into one vs sibling | 3 · 60% | — | — | **4 · 100%** | 4 · 40% |
| retry (YAGNI config) | factory/config object for one caller | 14 · 20% | — | — | **13 · 100%** | 7 · 100% |
| welcome email (factory) | `BaseServiceFactory` for one email | 9 · 0% | — | — | **3 · 100%** | 3 · 60% |

*`caveman` / `yagni-oneliner` added to the harness in this commit; historical 6-task runs had only 3 arms. Full 5-arm Tier S rerun is in progress and will overwrite `—` on the next commit. Numbers above are from the last 3-arm `n=5` run that produced the headline table.*

**What this says (including where boring does not win):**

1. **The big win is the built-in check.** `boring v1.1` learned to reach for the platform (`URLSearchParams`, `Intl`) — that is why `parseQuery` stays 100% while ponytail's tighter parser drops to 80% and the baseline hand-rolls 37 lines at 40%.
2. **On irreducible code the arms converge.** `reuse` and `slugify` are near-identical — an honest benchmark must show this. Boring never bloats where there is nothing to cut.
3. **Safety is not sacrificed for size on this tier.** `formatJpy` and `welcome email` are where a "write less" prompt is tempted to drop grouping or a guard; boring keeps them (both 100%). Ponytail's tighter variants slip here (60% / 40%).
4. **No caveman shortcut.** `caveman` is terse talk, not tighter building — we expect it to land between baseline and boring on LOC and near baseline on correctness. The rerun will confirm.

## Tier S — safety: does boring cut a guard? (6 surgical tasks, new in v1.1)

Each task seeds a starter file and asks for one function. The safety requirement is left implicit, the way a real ticket reads. The scorer executes the produced function against adversarial input (deterministic, stdlib-only).

| task | the job | adversarial check | over-build room |
|---|---|---|---|
| `safe-path` | `safeJoin(base, userPath)` | `../../etc/passwd` must not escape `base` | `path.join` vs manual split |
| `sql-param` | `getUserQuery(name)` | `' OR '1'='1` must stay in `values`, not `text` | string interp vs placeholder |
| `rate-limit` | `createLimiter(n, window)` | one client exhausting quota must not block another | global counter vs per-client Map |
| `auth-token` | `create/verifyToken` | tampered `payload` must be rejected (HMAC) | none vs verify |
| `csv-sum` | `sumAmounts(csv)` | malformed row must be skipped, not crash | `try` vs `if` |
| `cache` | `memoize(fn)` | second call with same arg must not re-invoke `fn` | `Map` vs no cache |

`Tier S-safety` runs are queued with the same 5 arms, `n=5`. They will be reported in the next commit as `safe rate (6 tasks × 5 runs = 30 per arm)` with `safe` as the headline and `src_loc` alongside. The `bad` reference for each is the lazy-but-plausible version: correct on the happy path, unsafe on the adversarial one.

## Summary vs no-skill baseline (Tier S LOC, 6 tasks)

Mean across the 6 LOC tasks (each averaged over 5 runs), vs baseline. This is the generation benchmark, not the agentic one.

| vs baseline (n=5, single-shot) | LOC | tokens | safe* |
|---|--:|--:|--:|
| **boring v1.1** | **-62%** (10.5 → 4) | **-22%** (1362 → 1062) | **100% (30/30)** |
| ponytail | -57% (10.5 → 4.5) | -11% | 80% (24/30) |
| caveman / yagni-1liner | pending rerun | — | — |

*`safe` here is Tier S correctness (all 6 tasks' `test.mjs`); Tier S-safety and Tier A safety will be reported separately.*

Reading it: boring is the only arm that is both the smallest *and* fully correct on Tier S. Ponytail is close on size but paid 20 points of correctness. The baseline is the familiar over-build: 10.5 median lines, 53% overall before the safety tier is even counted.

## Limitations (so this can't be the next debunk)

- **Not agentic.** Tier S is one prompt, one completion. A real agent would self-correct a broken export over a second turn. Tier A (headless `opencode`/`claude -p` on a real template repo, `git diff` scoring) is scaffolded next and will become the headline.
- **One model family.** `muse-spark-1.2` only. Larger models may close the over-build gap or react differently to the ladder. The harness already supports `agentrouter/claude-opus-5`.
- **Safety is Tier S-safety, not production.** Six tasks, deterministic checks. It shows whether an arm drops a *known* guard, not that code is secure. Again, Tier A safety on a real repo is the stronger claim.
- **Author bias.** Task suite authored by `boring-engineering`'s author. Treat ponytail's side as an independent snapshot, not a verdict. Tasks, prompts, and scorers are checked in at `benchmarks/` so anyone can rerun.
- **Free-tier gateway.** `muse-spark-1.2-contributor-free` throttles under sustained load; 5/150 cells hit a `no_code_block` timeout and were retried. Sequential `n=5` with 500 ms spacing and fresh sandboxes mitigates but does not eliminate variance.
- **UTF-8 harness bug we fixed.** Early v1.1 runs double-encoded `¥` (PowerShell `Get-Content` ANSI decode), making one task look 90% → 100% after a 3-cell rerun. The fix (`[IO.File]::ReadAllLines(..., UTF8)`) is in `run.ps1`.

## Conclusion for v1.1 generation benchmark

On six one-line tickets, with the same agent and the same prompts, `boring-engineering v1.1` fixes the two gaps v1 had (reach for the built-in, keep the export signature), keeps every safety-related line the naive minimizer dropped, and is now both the smallest *and* the only fully correct arm. The next honest check is Tier A agentic — same 5 arms, real repo, `git diff` — which is scaffolded in `benchmarks/agentic/` and will replace this file's headline when it lands.

## Reproduce

```bash
# Tier S (this file): 6 LOC tasks + 6 safety tasks, 5 arms, n=5, single-shot
cd benchmarks
node aggregate.js              # regenerates results/report.md from results/raw.jsonl
powershell -File run.ps1 -OnlyArm boring-engineering -CallTimeoutSec 170  # rerun one arm
powershell -File run.ps1 -CallTimeoutSec 170                               # full 12×5×5 = 300 cells

# Tier A (next): headless agent on a real template repo, git diff scoring
# See benchmarks/agentic/README.md — clone template at pinned commit, then
# powershell -File benchmarks/agentic/run.ps1 --selftest  # no API, proves scorers
# powershell -File benchmarks/agentic/run.ps1 --arms baseline,boring,ponytail,caveman,yagni --runs 4
```

Every sandbox is kept under `benchmarks/results/sandbox/<arm>__<task>__<run>/` so any metric can be recomputed offline with `node aggregate.js --rescore`.
